# 06. 受け入れ条件・トレーサビリティ

## 6.1 基本ゲート

仕様変更またはリリース前に、少なくとも次を実行し、結果を記録する。

```text
go build ./...
go test ./...
```

外部ツール・実機依存の試験は、環境変数やツールがない場合にスキップされることがある。その場合は「合格」ではなく「未実施（環境不足）」と記録する。

## 6.2 受け入れ条件

### AC-001 起動・管理

- [ ] `healthz` が正常時に `ok` を返す。
- [ ] 既存の健全なローカルインスタンスを二重起動しない。
- [ ] GUIが `/api/state` の状態を表示し、状態変更後に同期される。
- [ ] localhostの管理アクセス、LAN + 有効トークン、Tunnel経由の管理拒否がテストされる。

根拠: `internal/app/app_test.go`, `internal/server/server_test.go`, `ui_media_test.go`, `auth.go`。

### AC-010 画像

- [ ] 画像をアップロードして現在画像URLを取得できる。
- [ ] PNG/JPEGの拡張子付き公開経路が正しいContent-Typeで応答する。
- [ ] 画像変換失敗時に公開成功と扱わない。
- [ ] 新しいメディアを公開した後も、履歴ポリシーに従う。

根拠: `internal/imageproc/*_test.go`, `internal/server/server_test.go`, `ui_media_test.go`。

### AC-020 音声・動画・HLS

- [ ] ビデオプレーヤーモードOFF時に音声・動画系経路を受理しない。
- [ ] 動画はID付きplaylistとsegment名を使う。
- [ ] playlistと最低1セグメントの準備前にHLS URLを公開しない。
- [ ] 変換中はEVENT、完了後はVOD/ENDLISTになる。
- [ ] 別IDのsegmentを誤って返さない。
- [ ] 4,294,967,295 bytesちょうどは許可し、1 byte超過を拒否する。
- [ ] Content-Lengthがないストリームも実読込で超過を拒否する。

根拠: `internal/video/media_limit_test.go`, `publisher`/`page_hls`/`obs_http_acceptance` 関連テスト、`upload_limit_test.go`, `remote_media_test.go`。

### AC-030 履歴・お気に入り

- [ ] 通常履歴は起動時に消去される。
- [ ] 終了時に通常メディアと通常convertedが消去される。
- [ ] お気に入り本体・サムネイル・convertedがfavorites領域へ複製される。
- [ ] 再起動後にお気に入りがロードされる。
- [ ] 履歴選択はプレビュー対象を変更するが、公開状態を暗黙に変更しない。
- [ ] 公開切替は `Published` だけを意図通り変更し、OBSライブモードへ暗黙遷移しない。
- [ ] HLS実体が欠落した場合、変換済みとして再利用しない。
- [ ] 履歴リンクのコピー値が `http://` または `https://` で始まり、`/pub/<内部ID>` を含む完全URLである。
- [ ] 履歴欄に公開URL文字列を表示せず、リンクボタンからのみコピーできる。
- [ ] トンネル接続中はトンネルURL、未接続時はLAN URLをベースにし、内部識別子単体や管理トークン付きURLをコピーしない。

根拠: `internal/library/store_test.go`, `internal/server/server_test.go`, `audio_history_test.go`, `pub_route_test.go`, `inactive_video_test.go`, 履歴関連UIテスト。

### AC-040 キュー・画質

- [ ] 待機・実行中・完了・失敗と進捗を取得できる。
- [ ] 入力解像度がプリセット未満の場合に過剰な出力設定をしない。
- [ ] Auto画質がネットワーク測定値を利用する。
- [ ] 実行中の別ジョブをID違いで上書きしない。
- [ ] 失敗したジョブが成功・公開済みとして残らない。

根拠: `internal/video/*_test.go`, `music_playlist_test.go`, `ingest_status_test.go`。

### AC-050 OBS

- [ ] OBSキーを生成・更新し、正しいRTMP接続情報を取得できる。
- [ ] OBS入力から共有HLSと録画VODを生成できる。
- [ ] 選択したレイテンシ方式を表示し、準備前に公開しない。
- [ ] LHLS sinkがloopback・トークン・メソッド・ファイル名・サイズを検証する。
- [ ] MediaMTX経路が終了時に停止・掃除される。
- [ ] 方式失敗時に別方式へ無言フォールバックしない。

根拠: `internal/obsrtmp/*_test.go`, `obs_http_acceptance_test.go`, `music_radio_*acceptance_test.go`。

### AC-060 セキュリティ

- [ ] discovery応答に管理トークン・OBSキー・長期秘密がない。
- [ ] ペアリングPINが期限切れになり、試行回数制限が働く。
- [ ] ペアリング済み資格情報が `obs-relay` 以外の管理操作に使えない。
- [ ] パス traversal、危険なファイル名、巨大レスポンスを拒否する。
- [ ] 秘密値がログ・仕様書・テスト出力へ現れない。

根拠: `pairing.go`, `auth.go`, `server_security_test.go`, `lhls_sink_test.go`, `store_security_test.go`。

## 6.4 回帰テストの必須分類

バグ修正時は、単一の失敗テストだけでなく、次の組合せを確認する。

1. 現在メディアを別の履歴へ選択した直後に、遅延した変換完了が来る。
2. 公開状態を切り替えた直後に、プレビューと共有URLを再取得する。
3. 通常履歴とお気に入りで、同じIDの本体・thumbnail・convertedの保存先を比較する。
4. 通常HLS、OBS HLS、LHLS/LL-HLS/RTSPの経路を相互に切り替える。
5. localhost、LAN token、Tunnel public read、Tunnel adminを分けて検証する。
6. Content-Lengthあり・なし、上限ちょうど・超過、途中切断を検証する。

## 6.5 未実施の扱い

実機VRChat、特定GPU、外部サイト、Cloudflare、MediaMTX、FFmpegビルド機能に依存する試験をローカル単体テストだけで「受け入れ済み」としない。試験環境、使用ツールの版、入力、結果、スキップ理由を記録する。
