# 05. プラットフォーム・非機能要件

## 5.1 性能・容量

- URL取り込み、音声・動画ダウンロード、メディア変換の共通上限は `MaxMediaSourceBytes = 1<<32 - 1`、すなわち **4,294,967,295 bytes（4 GiB - 1）**。Content-Lengthが超過する場合と、ストリーム実読込で超過する場合の両方を拒否する。
- 現行実装では、ローカル動画アップロード入口だけが `maxLocalVideoUploadBytes = 8 GiB` であり、共通上限と不一致である。4GiB超のファイルを受け付けた後に下流処理で拒否・失敗し得るため、製品要件として上限を統一するか、「ローカル入口のみ8GiB」を正式な経路別仕様として明記し、受け入れ試験を分離することを推奨する（監査指摘 IMP-001）。
- 通常のmultipartアップロードは大きなデータをRAMへ全載せせず、`maxMultipartMemory = 32 MiB` を超える部分を一時ファイルへ逃がす設計とする。
- HTTPサーバーはReadHeaderTimeout 30秒、IdleTimeout 2分を設定する。
- 変換は長時間処理となるため、UIは受信進捗、ダウンロード、解析、変換、キュー進捗を区別して示す。
- 生成物はID単位に分離し、古いメディアのsegment名衝突やキャッシュ混入を防ぐ。
- ネットワーク測定値はAuto画質の補助値であり、実際のVRChat再生遅延や回線品質を保証しない。

## 5.2 可用性・障害時

- 起動時に既存の健全なローカルインスタンスを検出する。
- FFmpeg、MediaMTX、cloudflared、UPnPの前回残留状態を可能な範囲で掃除する。
- Cloudflare Tunnel切断時は状態を失敗/切断として表示し、再試行する。公開URLが得られない間は、得られたと偽装しない。
- 外部ツールが未導入または非対応OSの場合、該当機能をエラーにし、一般の画像・管理画面まで壊さない。
- 変換失敗時はキューを失敗状態にし、エラーを保持する。変換成功・公開成功と偽装しない。
- アプリ終了時の一部クリーンアップが失敗しても、残りのcleanupとHTTP shutdownを続行してログへ記録する。

## 5.3 データ保全

- 通常メディアは意図的な一時領域であり、再起動後の復旧を保証しない。
- お気に入りは再起動後に復元する唯一のメディア保全経路である。
- `state.json`、`favorites.json`、設定ファイルはatomic renameを用いる。
- ファイルコピーは0600相当のアプリ専用アクセスを基本とする。
- 「変換済み」フラグ、実ファイル、解像度一覧、公開URLのIDを整合させる。
- メタデータ更新ジョブは対象IDを検査し、現在対象が変わった後に別メディアを上書きしない。

## 5.4 ネットワーク

- 既定の待受は `0.0.0.0:8080`。`IMAGEPAD_HOST`, `IMAGEPAD_PORT`, `IMAGEPAD_ADVERTISE_HOST`, `IMAGEPAD_PREFER_TAILSCALE` で変更できる。
- LAN/Tailscaleの広告アドレスは到達可能アドレス検出で決める。Tailscale優先は明示設定時のみ。
- UPnP自動ポート開放は安全上の方針として通常起動で無効化される。RTSP公開に必要な状態は別途、現在の実装・UI表示に従う。
- Cloudflare Tunnelは外部公開URLを提供するが、管理APIの認証・公開拒否を迂回させない。
- LAN discoveryはUDP 45849、ペイロードと応答形式はBrowserRelayStreamer契約に従う。ただし発見情報に長期資格情報を含めない。
- UPnPはSSDPおよびルーターのWANIPConnection/WANPPPConnectionサービスを利用し、TCP/UDPマッピングを個別に追加・削除する。検出はlegacy方式とrace方式を持つが、ルーターの応答、二重NAT、CGNAT、ファイアウォールによって失敗し得る。
- UPnPの外部IPがグローバル到達可能かを判定し、プライベート、ループバック、リンクローカル、マルチキャスト、未指定、キャリアグレードNATのアドレスをグローバル公開先として扱わない。


## 5.5 クロスプラットフォーム

| 領域 | Windows | macOS | Linux |
|---|---|---|---|
| HTTP/画像/基本管理 | 対応 | 対応 | 対応 |
| ブラウザ・クリップボード・トレイ | OS実装 | OS実装 | unsupported実装を含む |
| FFmpeg/yt-dlp/cloudflared | アプリ専用bin自動取得候補 | アプリ専用binまたはPATH | PATHまたはローカルbin |
| MediaMTX自動取得 | amd64向け実装 | 自動取得を保証しない | 自動取得を保証しない |
| SteamVR | 凍結資産・現行統合対象外 | 対象外 | 対象外 |
| GPU音楽サイドカー | 対応契約・実機検証が必要 | 同左 | Linux契約資料・実機検証が必要 |

OS固有の「表示できる」「コンパイルできる」と、外部ツールを含む全機能の受け入れ完了は区別する。

### 5.5.1 Windows固有統合

- 通知領域トレイは管理GUIの起動、再接続、終了、電源復帰通知を担う。トレイが起動できない場合もサーバー本体を継続する。
- SteamVR関連の登録コード・マニフェストは凍結資産であり、現行アプリの起動・通常運用・受け入れ試験の対象外とする。SteamVR設定を変更・登録することを現行要件としてはならない。
- Windows固有の非表示プロセス、ネイティブウィンドウ、クリップボード、アイコン処理は、基本HTTP・ブラウザUIの必須条件ではない。

### 5.5.2 yt-dlp Cookieと診断環境

- Cookie保存領域はアプリ設定ディレクトリ配下とし、ディレクトリは0700、Cookieファイルは0600相当を基本とする。
- Cookie取得はローカルブラウザのDevTools接続を使用する環境依存機能であり、ブラウザ未導入時の成功を保証しない。
- yt-dlp診断ラボは本番取り込み経路と独立した診断機能であり、診断レポートにCookie値や長期資格情報を保存してはならない。


## 5.6 運用・ログ

- ログは起動、外部ツール、トンネル、クリーンアップ、HTTP異常を診断できる粒度とする。
- 管理トークン、OBSキー、Cookie、クライアント秘密値、URLに含まれる秘密をログへ残さない。
- Cookie等の秘密ファイルは仕様書・コミット・配布物へ含めない。
- 生成物、`outputs/`、秘密CookieはGit管理対象外とする。
- 同梱ライセンス・依存通知は `NOTICE.md` とアプリのOpen source noticesで案内する。

## 5.7 監査指摘・改善候補

| ID | 優先度 | 指摘 | 推奨対応 | 現状 |
|---|---|---|---|---|
| IMP-001 | 高 | ローカル動画アップロード上限8GiBと、共通メディア上限4GiB-1が不一致 | 入力経路の上限を統一するか、経路別仕様・下流拒否動作・UI表示を明文化して試験する | 未修正・仕様へ記録 |
| IMP-002 | 高 | `EnsureOBSStreamKey` 失敗時にOBSストリームキーが管理トークンへフォールバックする | 認証秘密を用途間で共有せず、キー生成・保存失敗時はOBSをfail-closedで停止する | 未修正・実装上のセキュリティ改善候補 |
| IMP-003 | 高 | `go test -race ./internal/server ./internal/obsrtmp` で、履歴URL発行行列とラジオ世代完了通知にデータ競合が検出された | 共有状態をmutexまたはimmutable snapshotで保護し、raceテストを受け入れゲートへ追加する | 未修正・通常テストは成功 |
| IMP-004 | 中 | 同じrace実行でラジオ終了待ちテスト2件がタイムアウトした | トラック終了・セッション終了・publisher終了の完了通知を単一の終了プロトコルへ整理し、Windowsを含む終了待ちを試験する | 未修正・環境依存か実装競合か要切り分け |
| IMP-005 | 中 | HTTPハンドラや補助処理に`context.Background()`起点の外部処理が残り、要求キャンセルやアプリ終了との伝播が弱い経路がある | リクエストまたはアプリケーションのroot contextを渡し、外部プロセスを`CommandContext`で終了可能にする | 部分対応・継続監査 |

上記は現行機能を未実装と判定するものではなく、要件と実装の一致、秘密分離、並行性、終了性を改善するための監査指摘である。

## 5.8 UI非機能契約

- 管理GUIの既存要素IDと主要API経路を維持する。
- 送信側は「送信中」、ホスト受信側は「受信中」と表示し、同じ進捗を二重表示して混同させない。
- HLS.jsのインスタンス寿命はPreviewControllerに集約し、同じメディアの状態更新だけで再生成しない。
- 通常動画、OBS、画像、空状態、変換中、アップロード中は排他的に描画する。
- 管理画面のプレビューは同一オリジンを優先し、共有用外部URLの可用性に依存しない。
