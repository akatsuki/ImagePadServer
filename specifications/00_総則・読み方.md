# ImagePadServer 包括要件・現状仕様書

## 文書の位置づけ

本書は、ImagePadServer 全体の**現行実装を基準にした包括仕様書**である。README、ユーザーガイド、アーキテクチャ、ロードマップ、機能別契約書だけを正とせず、実装コードとテストを突き合わせて、現在満たされている振る舞いを要件として固定する。

- 対象リポジトリ: `ImagePadServer`
- 基準版: `v1.6.2`（`internal/about/about.go`）
- 作成基準日: 2026-08-20
- 仕様の優先順位: **実行コードとテスト > 本書 > 既存の説明文書**
- リリース版との差分は Git のリリースコミットとタグを基準に確認する。

## 仕様状態の凡例

| 状態 | 意味 |
|---|---|
| **実装済み** | 現行コードで動作経路が存在し、テストまたは複数のコード根拠で確認できる。 |
| **実験的** | 実装は存在するが、対応プレーヤー・OS・外部ツール等の受け入れ範囲が限定される。 |
| **暫定** | 現在の動作を記録したもので、将来の改善余地または互換性上の制約がある。 |
| **未実装** | 文書・ロードマップ上の要求だが、現行の通常経路として成立していない。 |
| **凍結・歴史** | 資産や過去の判断として残すが、現行の通常起動・通常経路の要求ではない。 |

## 仕様変更の原則

- バグ修正では、まず本書の状態モデル・権限モデル・受け入れ条件に照合する。
- コメントや旧文書と実装が食い違う場合、現行コードとテストを先に確認し、本書の「差異・未確定事項」に記録する。
- 新機能を「実装済み」に昇格するには、実行経路、失敗時の挙動、権限、永続化、回帰テストを追加する。
- API、UI要素ID、公開URLの互換性を変更する場合は、章06の受け入れ条件と既存テストを更新する。
