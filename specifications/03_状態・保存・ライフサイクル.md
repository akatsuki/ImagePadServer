# 03. 状態・保存・ライフサイクル

## 3.1 メディア状態モデル

メディアIDごとに、次の状態を別々に保持する。1つのフラグから他の状態を推測してはならない。

| 状態 | 主な表現 | 意味 |
|---|---|---|
| 取り込み済み | `CurrentImage`/`HistoryItem` | 入力ファイルとメタデータが登録された |
| 現在選択 | `Store.current` | 管理GUIのプレビュー・次の操作対象 |
| 公開 | `Published` | 公開メディア経路から読ませる対象集合に含まれる |
| お気に入り | `Favorite`, `Persistent` | favorites領域へ保全される |
| 変換済み | `Converted`, `Resolutions` | IDに対応する生成物が保存され、復元可能 |
| 変換中 | queue item / publisher status | FFmpeg等が生成中で、公開ゲート前または更新中 |
| 失敗 | queue itemの失敗状態・エラー | 入力または外部ツールの失敗。成功扱いにしない |

特に「履歴選択 = 公開」「HLS生成済みフラグ = 実ファイル存在」「プレビュー表示 = 外部公開」とみなす実装は禁止する。

## 3.2 ディレクトリと永続性

`settings.Dir()` の配下をデータルートとし、既定の保存先は環境により次のように決まる。

```text
<データルート>/settings.json
<データルート>/media/                 通常メディアワークスペース
<データルート>/converted/<media-id>/  通常履歴の変換生成物
<データルート>/favorites/             お気に入りの本体・メタデータ
<データルート>/favorites/converted/   お気に入りの変換生成物
<データルート>/bin/                   自動取得ツールの候補
```

`IMAGEPAD_DATA_DIR` が設定されている場合はそれを優先する。Windowsでは `APPDATA/ImagePadServer`、その他は `os.UserConfigDir` 等を使用する。設定ファイルとメディアはアプリデータ配下に置き、入力メディアを実行ファイル置き場へ混在させない。

### 永続性表

| 対象 | 起動時 | 稼働中 | 終了時 | 再起動後 |
|---|---|---|---|---|
| `media/` の通常本体・通常履歴 | `NewStore` が全消去して再作成 | 一時保存 | `resetMediaWorkspace` が生成物とともに初期化 | 残さない |
| `converted/` | 全消去して再作成 | 通常履歴用に保持 | 初期化 | 残さない |
| `favorites/` | 消去しない。`favorites.json`をロード | 永続更新 | 消去しない | お気に入りを復元 |
| `favorites/converted/` | 消去しない | お気に入り変換を保持 | 消去しない | 変換済みを復元可能 |
| `settings.json` | ロード | atomic save | 消去しない | 設定・トークンを復元 |

この初期化方針は、現行コードの明示的な仕様である。通常メディアの永続化を期待する修正は、まず本書と `Store.Reset`/`NewStore` の設計を変更し、テストとリリースノートを更新する。

## 3.3 保存原子性と整合性

- `state.json` は一時ファイルへ書いてrenameする。
- `favorites.json` も一時ファイル経由で保存する。
- `MarkConverted` は入力ファイルの存在・非ディレクトリを確認してから生成物をコピーする。
- HLS公開はplaylistとセグメントの準備状態を確認し、空のplaylistや別IDの生成物を公開しない。
- 変換完了が別の現在選択後に到着しても、ID付き更新APIを使い、別メディアのサイズ・メタデータを上書きしない。
- 不完全なコピー・外部ツール失敗・セグメント欠落を `Converted=true` または公開成功にしてはならない。

## 3.4 ライフサイクル

1. 起動前に前回のFFmpeg、MediaMTX、cloudflared、不要なUPnP状態を掃除する。
2. 設定を読み、音楽プレイリストのcanonical heightをプロセス内で固定する。
3. `library.NewStore` が通常メディアと通常convertedを初期化し、お気に入りを読み込む。
4. HTTP listener、GUI、LAN discovery、トンネル管理、OBS受信を開始する。
5. 取り込み、変換、公開、履歴・お気に入り操作を提供する。
6. 終了時にOBS、FFmpeg、UPnP、cloudflared等を停止し、HTTPサーバーをshutdownする。
7. `resetMediaWorkspace` が通常メディアと生成物を初期化する。

クリーンアップの一部が失敗しても、ログを残して他の終了処理を継続する。起動時・終了時の初期化や外部プロセス掃除を「ユーザーが手動で行う」ことを通常要件にしない。

## 3.5 キュー状態と公開ゲート

キューは少なくとも `queued`, `running`, `completed`, `failed` と進捗・エラー情報を扱う。新しいジョブを優先する制御が存在するため、表示順・実行順を固定FIFOと仮定しない。

通常HLSの公開ゲートは次の順である。

1. IDを確定する。
2. 生成先をID専用名にする。
3. playlistと最初のセグメントを待つ。
4. 状態とURLを公開する。
5. 変換終了時にVODへ確定する。
6. 新しい入力・再指定・キャンセル時に古いIDの生成物と公開状態を無効化する。

## 3.6 既知の注意点

- `Store.SetFavorite` のファイル複製とJSON保存は複数操作にまたがるため、途中のI/O障害に対する完全なトランザクションは保証されない。
- 履歴上限は非お気に入りに適用され、お気に入りは除外される。お気に入り数に別上限はコード上確認できない。
- 外部ツールの作業ファイル・Cookie・認証情報は、仕様書やログに値を記録しない。
- HLSの「変換済み」状態はメタデータだけでなく、実ファイルとIDの一致を検証して扱う。
