# Playlist Hybrid Overlay Implementation Plan

> **Subagent execution:** Use `docs/superpowers/plans/2026-07-11-playlist-subagent-execution.md`. Program-clock and final acceptance work are Sol-owned and require a fresh Sol review.

> **For agentic workers:** REQUIRED SUB-SKILL: Use `superpowers:subagent-driven-development` or `superpowers:executing-plans` to implement this plan task-by-task. Steps use checkbox syntax for tracking.

**Goal:** Add a persistent program-output path for playlist radio that keeps monotonic timestamps through every transition and supports dynamic overlays, while preserving the existing copy-remux RTSP path as a separately started compatibility session during rollout.

**Architecture:** Keep `radio-track-<id>.mp4` as the pre-rendered source of truth. A session-owned program clock, compositor, and encoder consume decoded track frames plus an optional RGBA overlay and emit one continuous H.264/AAC MPEG-TS stream. Program output remains active even when the overlay is visually empty. Track decoders are replaceable source workers behind that boundary: they may stop/start per MP4, but never reset the output clock, compositor, encoder, MediaMTX path, RTSP URL, or publisher. The black fallback is generated by the program clock during every source handoff, so output PTS remains strictly monotonic. The legacy copy lane is tested and started as a separate compatibility session; packets from it are never hot-swapped into an existing program publisher.

**Tech Stack:** Go, FFmpeg, MediaMTX, existing `internal/playlist`, `internal/video`, `internal/obsrtmp`, browser UI.

## Global Constraints

- Complete `docs/superpowers/plans/2026-07-11-playlist-streaming-remediation.md` Tasks 1, 2, 4, 5, 6, and 7 before enabling this plan's program output. Its Task 3 is implemented by this plan's Tasks 3-6.
- Default delivery profile remains `rtsp-ultra`. Before the program lane passes rollout gates it may start the legacy copy session; after activation it starts the persistent program session even with no visible overlays.
- Never restart MediaMTX, RTSP gate, or the public RTSP URL merely because the overlay state changes.
- Program mode is unavailable until its encoder preflight succeeds; rollout keeps the legacy copy session as an explicit start-time compatibility choice.
- A decoder or overlay-process error must emit black/fallback through the still-running program encoder within two seconds. Persistent encoder or publisher death is session-fatal.
- Overlay output must stay H.264, yuv420p, AAC 48 kHz stereo, no B-frames, and carry repeat headers/AUD for AVPro compatibility.
- The compositor input size comes from the active canonical resolution loaded at ImagePadServer startup. Changing the detailed setting does not resize a running compositor; it applies after ImagePadServer restarts.
- The program clock owns output PTS at 30 fps and the 48 kHz audio sample clock. Track decoder PTS is translated at ingestion and is never forwarded to MediaMTX directly.
- A track decoder is intentionally not a literal permanent FFmpeg process: switching arbitrary MP4 inputs requires replacing that source worker. The persistent boundary is the output-side program clock/compositor/encoder, which is what prevents receiver-visible discontinuities.
- HLS and RTSP continue to be served from the same persistent MediaMTX path.
- Do not create live waveform rendering for tracks. Pre-rendered MP4 remains the track visual source.

## Rollout Order

1. Ship Tasks 1-2 with overlay disabled by default.
2. Land Tasks 3-4 behind the unavailable preflight gate.
3. Land Tasks 5-6 with explicit start-time compatibility selection and in-program fallback recovery.
4. Complete Task 7 and only then consider enabling notifications by default for GPU-capable systems.

## Plan Review

- Scope is limited to playlist radio; normal video publishing and OBS ingest are not modified.
- The copy pipeline remains an independently testable path throughout every task.
- Every decoder/overlay failure has a program-generated recovery path that preserves MediaMTX ownership, encoder identity, and public RTSP identity; encoder death is explicitly fatal.
- No task depends on a future unspecified interface; all new types and state boundaries are named above.
