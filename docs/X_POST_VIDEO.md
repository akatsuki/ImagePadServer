# X投稿を動画にする

X投稿の本文・引用本文をVOICEVOXで読み上げ、その後に添付写真/動画を最大4つ、投稿内の順序で表示する。素材間にはCoverFlowを入れる。縦素材は左に素材・右に本文、横素材は全画面に配置する。縦素材1つだけの場合は最初から2画面とし、読み上げが終わってから元動画を再生する。下端のバーは表示しない。

投稿ページと右側パネルは、静止画版と同じプロフィールアイコン・表示名・ID・投稿日時・本文の描画を使う。外枠・プロフィール・日時・文字サイズは固定し、長文は本文だけを読み上げに合わせて滑らかにスクロールする。短文は静止したまま。引用は固定の角丸ボックスに収め、引用本文を読む間も元投稿の読み終わった本文位置を保持する。本文の長さによる改ページは行わない。背景と素材周囲の余白は、CoverFlow中も含め、選択したライト（白）／ダーク（黒）に揃える。

スクロール時刻はVOICEVOXの文・句ごとの音素長と無音区間を、話速と完成WAVの長さに合わせて求める。句の内部は表示行の位置で補間する方式で、単語ごとの強制アラインメントではない。音声の休止中は本文も止まり、読み上げ終了後のCoverFlowや縦素材のパネルでは最終表示を引き継ぐ。スクロールが必要な本文で時刻情報が得られない場合は、途中までの静止表示で成功扱いにせず生成エラーにする。

## 使い方

1. Node.js 20以降を用意し、アプリを起動する。VOICEVOXは起動時に自動準備する。初回は公式CPU版ENGINE 0.25.2（CORE・モデル・辞書を含む、約1.9GB）を取得・検証・展開し、次回から再利用する。
2. 動画機能を有効にし、「リンク」へX投稿URLを入力する。
3. 入力欄下に出る「Xの投稿を動画にする」をオンにする。声・スタイルを名前で選び、読み上げ速度を調整する。声一覧更新・試聴もこの場所で操作する。
4. 「リンク動画を変換して公開」で生成する。動画変換キューへの追加も利用できる。生成中は「生成を中止」でキャンセルできる。

スイッチをオフにすると既存の投稿画像化を使う。X以外のURLやファイル入力ではX設定を表示しない。

生成中の進捗欄に、変換済み/全体のフレーム数と映像変換の残り時間の目安を表示する。現在のジョブの実測速度で更新し、最初の5秒間または30フレーム未満は「計算中」とする。進捗通知は最大約2回/秒に抑え、最後のフレーム数は必ず通知する。映像変換の後は「音声と動画を仕上げ・検証中」に切り替える。取得・TTS・音声処理・最終検証は映像の残り時間に含めない。

最後に生成で使用した声・スタイル・話速を1件だけ記憶する。保存/復元ボタンはない。試聴、受付失敗、本文が空でTTSを省略した生成では記憶した設定を変えない。前回の声がエンジンからなくなった場合は、利用者が選び直す。

X設定欄にVOICEVOXの準備状況・進捗を表示する。完了すると声一覧を取得する。失敗時は「準備を再試行」、取得中は「準備を中止」を使える。中止後に自動再開しない。アプリ/HTTP起動は準備完了を待たない。

アプリ内エンジンは `http://127.0.0.1:50121` で動かす。既存のVOICEVOXや50021のサービスを停止・変更しない。前回使った外部エンジンがある場合は接続先を維持し、「アプリ内VOICEVOXを使う」で明示的に切り替える。初回の準備にはアーカイブと展開先の空き容量が必要で、約10GiB以上の空きを事前検査する。取得したファイルは `settings.Dir()/tools/voicevox`（標準Windowsでは `%APPDATA%/ImagePadServer/tools/voicevox`）へ置く。破損した版は `.incomplete-*` に退避して再取得する。自分で起動したプロセスだけをアプリ終了時に終了する。

公式パッケージ内の利用規約・依存ライセンス・話者情報を保持する。[取得元と版](https://github.com/VOICEVOX/voicevox_engine/releases/tag/0.25.2) を固定しSHA256を照合する。設定・プリセットはアプリ内の専用ファイルを指定し、辞書登録等の変更APIは無効化する。公式ENGINEの標準ユーザー辞書は読み込み先を変更するオプションがないため参照されるが、アプリから登録・変更しない。

読み上げるのは本文と引用本文だけ。表示名・ID・メンション・URLを読み上げから除く。本文の表示では静止画版と同じリンク整形を使い、外部リンクの表示URLを整え、添付メディアのリンクを省く。元の本文とUTF-16 entityは読み上げ用に保持し、表示行を本文だけの読み上げ位置へ対応させる。必要なVOICEVOXクレジットは本文カード/パネル末尾へ入れる。英語専用TTSは初版の範囲外。

## ビルド

Windows用の開発ビルドはリポジトリで次を実行する。Go、Rust/Cargo、Node/npmが必要。

```powershell
pwsh -NoProfile -File scripts/build-xpost-video.ps1
```

生成先は `build/xpost-video/imagepadserver.exe`。同じディレクトリの `xpost-compositord.exe` も必要。取得スクリプトとreact-tweetはexeに埋め込むため、`x-post-image/` やnode_modulesのコピーは不要。Node.js 20以降のランタイムは必要。FFmpeg/FFprobeは既存の動画機能と同じものを使う。

v1.9.0の配布ZIPには、各OS/CPUに対応した`xpost-compositord/`と第三者ライセンス通知を同梱する。LinuxではZIPを展開して使用する。単体のLinux実行ファイルは互換性のため引き続き公開するが、X動画化には同梱ヘルパーが必要。macOSのアプリにはUniversal版の合成ヘルパーを同梱する。

## 初版の範囲と確認状態

wgpuデバイスと素材をジョブ内で再利用し、静止区間では描画済みフレームを再利用する。スクロール本文は一度描画した1024px高までのタイルをGPUのUVで切り出し、フレームごとの文字描画は行わない。全画面にそのまま置ける横動画は合成を省き、最終映像は1回のH.264エンコードからMP4/HLSへmuxする。素材ダウンロードは容量制限つきのストリーム保存で行う。

Windowsでは書き出しworkerとその子プロセスをJob ObjectのCPU20%上限内で実行する。アプリ内VOICEVOXも1合成スレッド・専用Job ObjectのCPU20%上限で動かす。両者の合算20%制限ではない。外部エンジンとサーバーの増分、VRChat併用での総負荷と最短時間は未評価。NV12転送、非同期readback、ジョブ間cacheは後続最適化とする。

Windowsの実wgpu/FFmpegを使ったfixture生成、音声境界、MP4全decode、HLSのprepared publication、CPU制限、ブラウザの設定表示を確認した。公式VOICEVOXの実取得・展開・起動、43話者の一覧とPCM生成、再利用・終了も確認した。実X投稿の取得・実VOICEVOX読み上げ・1080p GPU生成・MP4/HLS検査も確認した。実投稿をGUIで公開する一連の操作、VRChat再生、macOS/Linuxの実行は未確認。詳細と再実行手順は [実装記録](verification/xpost-video/implementation-ledger.md) を参照する。一般リリースの配布資格化とは別の開発ビルド。
