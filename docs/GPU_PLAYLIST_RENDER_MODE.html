4. 責任分担

GUI / Player

  • 停止・曲変更の検知
  • 実際に表示済みのplayback headを報告
  • TransitionRequestをepoch付きで送る
  • GPUへ直接stop命令を出さない

CPU / Playlist Controller

  • artwork / text / fallbackを曲単位で生成
  • spectrum / loudness / scroll loopをtimeline化
  • headとqueue tailを検証
  • TransitionPlanとaudio fadeを確定

GPU Compositor

  • static textureとtimelineを保持
  • frame indexからscroll/text/fadeを参照
  • bounded surface ringでmulti-frame合成
  • 停止時はnormal submit停止→in-flight drain→fade tail

NVENC / Sidecar

  • slotごとのinput/output resourceを管理
  • render fenceをwait
  • output fenceをsignal
  • compressed bitstreamだけCPUへ返す

Mux / Stream Line

  • sequence/PTS順に出力
  • audio fadeを同じTransitionPlanで適用
  • 全slotのdrain後にFlush/EOS
  • 部分的なprefix出力を成功扱いしない

通常music mode

  • CPU production rendererを使用
  • GPU sidecarを暗黙起動しない
  • playlist transition state machineを実行しない
  • GPU modeは明示的diagnostic/playlist入口のみ

5. 運用指標とguardrail

正しさ

  • sequence/PTS: 単調増加・欠落なし
  • epoch: 古い曲のevent混入なし
  • transition: start/end frame一致
  • audio sync: video fadeと同じPTS
  • decode: video/audio pass

GPU pipeline

  • batch size: 実値 / 最大8
  • in-flight: slot occupancy
  • render: submit / fence wait
  • NVENC: submit / drain
  • overlap: render(N+1)とdrain(N)

遅延

  • transition latency: request→fade開始
  • queue depth: head/tail差
  • backpressure: block時間
  • drain time: stop→fade完了
  • startup: asset/GPU/NVENC init

資源

  • slot reuse: fence前の再利用=0
  • memory: surface / output / buffer peak
  • CPU: asset/analysis/directive queue wait
  • transport: request bytes / RPC count
  • readback: pixel bytes=0

障害・回帰

  • partial: BatchError後はsessionをpoison
  • Flush: 全slot drain + EOS
  • fallback: normal mode CPUへ暗黙切替しない
  • wire: null/empty sequenceを検証
  • quality: GPU parity未達はproduction不可
運用上の判断基準: batch/RPCが速くなっただけではGPU成功としない。track preparation、GPU render、fence wait、NVENC submit/drain、mux、transition latencyを含むend-to-endで測定し、同一scene/PCM/metadata/artwork/解像度/FPS/frame count/PTSのCPU baselineと比較する。通常music modeのCPU production routeにはGPUを混入させない。
